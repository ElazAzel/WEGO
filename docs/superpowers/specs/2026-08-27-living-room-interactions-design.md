# WEGO: интерактивная комната, инвентарь и экипировка

## Цель

Превратить комнату из набора визуальных hotspot-зон в сохраняемое игровое пространство. Каждое значимое касание должно менять окружение или состояние Вего, а купленные предметы должны попадать в инвентарь, устанавливаться в комнату или надеваться на персонажа.

Первая реализация сохраняет текущий мягкий пастельный дизайн, layered DOM-сцену и локальный preview, а состояние проектируется так, чтобы его можно было синхронизировать с API и Telegram-подарками.

## Почему меняем текущую модель

Сейчас `WorldSnapshot.roomObjects` хранит только уровень и время последнего взаимодействия. Это позволяет начислить награду, но не позволяет восстановить выключенный свет, закрытые шторы, готовый чай или установленный предмет. Магазин добавляет ID в `unlockedItemIds`, но не разделяет владение, экипировку и слот интерьера.

## Выбранный подход

Используем доменный snapshot как единственный источник истины, а сцену оставляем тонким renderer-адаптером:

1. Действие пользователя создаёт типизированный world action.
2. Доменный reducer проверяет действие и возвращает новый snapshot с реакцией.
3. Zustand сохраняет snapshot и экономическую транзакцию.
4. Сцена читает snapshot и показывает состояние через слои спрайтов и короткие анимации.
5. API получает тот же контракт для будущей синхронизации пары.

Полный перенос сцены на Pixi в эту итерацию не требуется: DOM-слои уже дают доступность, простую проверку кликов и меньшее количество инфраструктуры.

## Доменная модель

### Состояние окружения

В `WorldSnapshot` добавляется обратно совместимое поле `environment`:

```ts
interface RoomEnvironmentState {
  lamp: "on" | "off";
  curtains: "open" | "closed";
  table: "empty" | "tea-ready";
  plants: "healthy" | "needs-care";
  window: "quiet" | "rainy";
}
```

Начальные значения: `lamp: "on"`, `curtains: "open"`, `table: "empty"`, `plants: "healthy"`, `window: "quiet"`.

Старые сохранения без `environment` проходят через `normalizeWorld` и получают эти значения. Некорректные или неизвестные значения заменяются defaults.

### Инвентарь и экипировка

Сохраняем `unlockedItemIds` как источник владеемых предметов для обратной совместимости и добавляем явное представление экипировки:

```ts
type RoomSlot = "sofa" | "rug" | "lamp" | "table" | "shelf" | "plants" | "wall";

interface EquippedRoomItems {
  [slot: string]: string | null;
}

interface EquippedWegoItems {
  outfit: string;
  accessory: string | null;
  emotion: string | null;
}
```

В snapshot появятся `equippedRoomItems` и `equippedWegoItems`. Покупка только добавляет ID во владение. Установка предмета меняет соответствующий слот. Один предмет нельзя установить в несовместимый слот.

Каталог получает машинно читаемые поля: `kind`, `slot`, `assetId`, `sparkPrice`, `starsPrice`, `behavior`. Повторная покупка уже принадлежащего предмета запрещена на клиенте и сервере.

## Игровые взаимодействия

### Окружение

- Светильник: `off ↔ on`; меняется glow-слой и CSS-класс освещения.
- Окно: `open ↔ closed`; переключается слой штор и короткая реакция Вего.
- Столик: `empty → tea-ready`; появляется чайник/чашки, повторное нажатие собирает чай и возвращает состояние в `empty`.
- Растения: `needs-care → healthy`; обычное состояние может стать `needs-care` после rollover/долгого отсутствия.
- Диван и ковёр: запускают play/tidy-анимации и увеличивают соответствующий уровень объекта.
- Персонаж: отдельные tap/pet реакции, меняющие нужды и эмоцию, но не перекрывающие клики по предметам.

Для повторяемых переключателей визуальная реакция срабатывает каждый раз, но награда ограничивается существующими дневными guardrails. Это исключает бесконечный фарм Искр на включении света.

### Типы action

Добавляется доменный action `room_interact` с полями `objectId`, `interaction` и `at`. Reducer валидирует допустимые пары:

```ts
type RoomInteraction =
  | { objectId: "lamp"; interaction: "toggle" }
  | { objectId: "window"; interaction: "toggle-curtains" }
  | { objectId: "table"; interaction: "serve-tea" | "collect-tea" }
  | { objectId: "plant"; interaction: "water" };
```

Невалидное действие не меняет snapshot и возвращает понятное сообщение. Для API action должен оставаться идемпотентным по `id`.

## Renderer и ассеты

`LivingRoomScene` получает `environment` и `equippedRoomItems` и отображает слои в порядке:

1. архитектурный фон;
2. шторы/световые эффекты;
3. базовые предметы комнаты;
4. установленные косметические слои;
5. Вего;
6. интерактивные кнопки и feedback.

Нужны прозрачные состояния/спрайты для закрытых штор, чайника с чашками и, при необходимости, состояния растения. Glow светильника можно сделать CSS-слоем, если отдельный PNG не нужен. Все ассеты живут в `apps/web/public/assets/rooms/v3` и не заменяют исходные изображения.

Если предмет не найден или ассет не загрузился, renderer использует базовый слот и не ломает сцену. Установленный предмет отображает `aria-label` с текущим действием и state hint.

## UI магазина и гардероба

Существующая `ShopSheet` превращается в каталог с фильтрами «Интерьер», «Образы», «Аксессуары», «Эмоции», «Моё». Для принадлежащего предмета вместо цены показываются:

- «Установить» для интерьера;
- «Надеть» для одежды;
- «Применить» для эмоции;
- «Снять» для активного предмета.

`WardrobeSheet` получает те же данные из единого каталога и не дублирует логику владения. После покупки за Искры UI сразу обновляет инвентарь. После оплаты Stars предмет появляется только после подтверждения платёжного webhook; для локального preview предусмотрен явный dev fallback без имитации реального платежа.

## API, Telegram и сохранение

Локальный store остаётся рабочим без сети. API добавляет snapshot environment/equipment в world sync и возвращает каталог с `behavior`, `slot` и asset IDs. Server-side validation повторяет доменные ограничения.

Telegram Stars продолжает использовать существующий invoice flow:

- покупка предмета добавляет его получателю в owned items;
- подарок партнёру добавляет предмет в его инвентарь;
- экипировка выполняется отдельным authenticated world action;
- webhook не должен самовольно надевать подарок.

## Ошибки и пограничные случаи

- старый snapshot нормализуется без потери `unlockedItemIds` и `outfitId`;
- неизвестный `itemId` не устанавливается;
- нельзя потратить Искры при недостаточном балансе;
- повторный action с тем же ID не даёт вторую награду;
- сетевой сбой оставляет локальное действие в offline queue;
- пропавший ассет заменяется базовым предметом и пишет диагностический warning без падения приложения.

## План проверки

1. RED/GREEN тесты доменной нормализации environment/equipment.
2. RED/GREEN тесты reducer для лампы, окна, чая и растений.
3. Тесты покупки, владения, установки и снятия предмета.
4. API-тесты каталога, world action и подарка.
5. UI-тесты доступных кнопок состояния и гардероба.
6. Production typecheck/build.
7. Локальный browser smoke-test: каждый объект меняет визуальный state, предмет из магазина появляется в inventory и устанавливается в слот.

## Критерии готовности

- клик по лампе видимо переключает свет;
- клик по окну видимо переключает шторы;
- клик по столику создаёт и собирает чай;
- предмет, купленный за Искры, остаётся в инвентаре после перезагрузки;
- предмет интерьера можно установить/снять;
- образ и аксессуар можно надеть/переодеть;
- старые локальные сохранения продолжают открываться;
- все проверки проходят, а локальная страница работает на `http://127.0.0.1:5173/wego`.
