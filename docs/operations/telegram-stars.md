# WEGO: Telegram Stars и экономика

## Модель экономики

Искры — бесплатная внутриигровая валюта, которая не покупается за деньги, не выводится и не конвертируется в Stars.

- Личный check-in: `+10` тому, кто его заполнил.
- Совпадение check-in обоих: `+5` каждому, без обнуления личной награды.
- Общий дневной кап регулярных наград: `80 Искр на пользователя`.
- Поглаживание: максимум 3 оплачиваемых награды в день, cooldown 20 минут.
- Сохранение памяти: максимум 3 награды в день.
- Одна награда за конкретный тип мини-игры в день.
- Недельная серия и подарок не должны превращаться в долг или повод для претензий.

Плановые источники и стоки калибруются по типичной паре: около `223 Искр в неделю` дохода и ценовые тиры `20 / 90 / 320 / 600+ Искр`. Магазин должен получать новый микро-контент еженедельно, средний сет ежемесячно и сезонный сет ежеквартально.

Покупки не повышают `affection`: тепло Wego растёт только от действий пары.

## Локальный запуск

Без конфигурации бота endpoint `/v1/billing/invoices` возвращает `503 BILLING_NOT_CONFIGURED`. Это намеренно: локальный preview не должен создавать настоящие платежи.

Минимальные переменные API:

```env
TELEGRAM_BOT_TOKEN=...
TELEGRAM_BOT_USERNAME=wego_bot
TELEGRAM_WEBHOOK_SECRET=случайная-длинная-строка
TELEGRAM_BILLING_ENABLED=true
```

`NOTE_ENCRYPTION_KEY` и `NODE_ENV=production` также должны быть заданы в production. Токен бота не попадает в клиентский bundle и не логируется.

## Поток Stars-покупки

1. Клиент просит сервер создать invoice только по `itemId`.
2. Сервер берёт цену из каталога, определяет региональный тир по подтверждённому Telegram-профилю и создаёт invoice в валюте `XTR`.
3. Для подарка сервер принимает только `recipientUserId` партнёра из того же `space_id`. Наценки за подарок нет.
4. Клиент не открывает предмет после callback `openInvoice`.
5. Webhook с `successful_payment` проверяет secret, payload, пользователя, товар и order id.
6. Сервер один раз записывает Telegram charge id, выдаёт entitlement получателю и начисляет ему фиксированные `+10 Искр` с отдельным ledger idempotency key.

Для поддержки нужен отдельный `/paysupport`-маршрут бота с ручной сверкой по `purchaseId` и `telegram_payment_charge_id`. Refund должен менять статус покупки на `refunded` и отзывать entitlement согласно политике продукта; повторный webhook не должен выдавать предмет или бонус повторно.

## Живой мир и коллекция

У предмета один жизненный цикл: `catalog → purchase → owned → equipped`. Покупка за Искры в локальном preview сразу добавляет `itemId` в `world.unlockedItemIds`; Stars-покупка становится owned только после подтверждённого webhook. Подарок попадает в инвентарь адресата и не надевается автоматически.

Состояние окружения хранится в `world.environment`: лампа (`on/off`), шторы (`open/closed`), чай на столике (`empty/tea-ready`), растения и окно. Эти действия не являются источником бесконечных Искр. Экипировка хранится отдельно в `equippedRoomItems` и `equippedWegoItems`, поэтому пользователь может менять предметы без повторной оплаты и снимать их.

Старые локальные snapshot без новых полей проходят через `normalizeWorld`: базовые значения добавляются, неизвестные слоты отбрасываются, а `unlockedItemIds` и текущий outfit сохраняются. Для постоянного хранилища подготовлена миграция `db/migrations/0002_world_environment_equipment.sql` с JSONB-снимком мира и idempotency-таблицей действий.

## Региональные тиры

Стартовая матрица:

| Тир | Языковые группы | Множитель |
| --- | --- | ---: |
| A | US / EU / UK и остальные | 1.0 |
| B | RU / TR / AZ | 0.7 |
| C | KZ / KG / UZ / TJ / TM | 0.5 |
| D | отдельные low-income рынки после данных | 0.3 |

Это стартовая гипотеза, а не вечный прайс-лист. Через 2–3 недели смотрим 90–95-й процентиль естественного заработка и квартально пересматриваем кап, цены и частоту контентных дропов. Региональная цена не должна давать функционального преимущества и не является обменом Stars на Искры.
